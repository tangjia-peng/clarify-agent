# Clarify Agent
### 通过自主追问挖掘用户需求的 RAG 决策规划系统
`旅游为首个验证场景 · 能力层与知识层解耦，换知识库即可迁移至考研 / 职业规划`

> **一句话**：独立设计可量化、可复现的 A/B/B2 对照实验，证明「追问式需求澄清」与「RAG 事实锚定」的独立价值，并把验证有效的方案反哺产品。

---

## 为什么做
规划类需求天然「说一半」：用户说不清需求，公共平台千人一面、整理耗时，AI 有知识库却答非所问。
→ 三类痛点：**需求挖掘难 · 事实不可靠 · 响应要快**
→ 核心判断：**问对问题是最大的杠杆。用户负责说什么，Agent 负责问什么**——把提问负担从用户侧转移到系统侧。

## 做了什么（MVP → V3 三步迭代）
- **V1（MVP）**：最小闭环打通 MCP + RAG「能查、能生成」，验证主链路可行
- **V2（追问）**：接入 `ask` 工具，模型自主判断是否追问用户的隐藏潜在需求
- **V3（优化）**：复用问答轨迹做二次检索重生成（即实验中的 B2），省成本、提准确率
- 形态：手写 Agent 循环 + MCP 工具 + RAG 向量库 + Web / CLI 双端

## 怎么验证
- **A/B/B2 三模式隔离变量**：A 直接生成 / B 先追问 / B2 复用 B 轨迹 + 二次检索（RAG 是唯一变量）
- **20 case × 5 类**：完全 / 说一半 / 模糊 / 不合理 / 不该答应，每题存档隐藏需求与攻略要点
- **跑题 → 裁判 → 录入**自动化链路；代码计数 + 骨架预填 + 录入兜底抑制 LLM 幻觉
- **三层指标**：需求侧（满足率 / 覆盖率）· 事实侧（瞎编率 / 准确率）· 体验侧（白问次数）

## 关键结果（成绩单 2026-11-19）

| 指标 | A | B | B2 | 结论 |
| --- | --- | --- | --- | --- |
| 需求满足率 | 36.4% | 76.1% | 77.5% | 追问 **+40pp** |
| 要点覆盖率 | 37.5% | 66.3% | 74.0% | 追问 +28.8pp / RAG +7.8pp |
| 硬信息准确率 | — | 50.5% | **77.0%** | RAG **+26.6pp**（主证据） |
| 瞎编率 | — | 27.2% | 17.8% | −9.4pp（辅证） |

> B2 需求率几乎不涨是**正确的**：它复用 B 的澄清结果、只补知识料——该平的就平、该涨的涨，证明归因干净。

## 两个核心优势
1. **问对问题是最大的杠杆**：与其教用户写提示词，不如让 Agent 主动提问、引导用户给出细节。
2. **可迁移**：能力层与知识层解耦，同一套追问引擎与评估体系换库即用，边际成本随场景递减。

**30 秒电梯**：我实习时做了 Clarify Agent，核心判断是大部分用户说不清需求，与其教用户写提示词，不如把「问什么」交给 Agent。用 A/B/B2 对照实验验证：追问把需求满足率从 36% 提到 76%，RAG 把硬信息准确率从 50% 提到 77%；B2 需求率不涨恰好证明变量隔离成功。最后把方案落地到了产品。
