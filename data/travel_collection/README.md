# 小红书旅游知识库采集说明

目标为50个城市、每城3篇独立旅游攻略或经验笔记，共150篇。实际数量、各城缺口与校验结果以 `collection_status.json` 为准；逐篇浏览见 `COLLECTION_INDEX.md`。只把已实际读取并保存正文的笔记计入数量，不用标题、搜索片段或空文件补数。

## 授权与来源

用户于2026-11-15在本次项目对话中确认“作者都同意了”，本批次据此按已获作者授权处理。该记录是用户确认，未另行向各作者核验，不编造授权截图或平台证明。

来源仅为小红书/rednote笔记。公开搜索与其他站点的参考链接仅用于发现原帖URL，实际内容由正常浏览器读取原帖页面。每篇Markdown保留城市、标题、作者、页面显示时间和原帖链接；实际采集时间等详细记录保存在 `source_records/<笔记ID>.json`。不推断页面未显示的年份、真实出游日期或当前有效价格。

## 正式文件与格式

正式资料平铺保存到项目的 `knowledge/`，文件名为“城市_序号_笔记ID_标题.md”。现有RAG通过 `iterdir()` 读取该目录，不需要修改Agent、前端或检索入口代码。

每篇使用“简短来源信息＋一份完整原文＋一句覆盖范围说明”的精简结构：

1. 标题采用“城市｜来源笔记标题”，随后列出城市、作者、页面显示时间和原帖链接。
2. “原始正文”区只保存一份页面 `#detail-desc` 实际展示的完整文字，不删减、不改写、不纠错。
3. 末尾注明：“仅保存页面可见文字正文；图片、视频、评论未转录。”

不再在正文前重复摘录路线、预算、交通、住宿、美食和避坑六类索引，也不添加段号、空字段占位或未归类段落统计。正文中的相关内容仍原样保留。`original-body:start` 与 `original-body:end` HTML标记用于准确定位原文，供本地校验使用。

授权依据、正文SHA-256、采集时间、作者主页和图片/视频链接等详细元信息保留在 `source_records/`；核验结果写入 `collection_status.json`。这些信息不再附加到供RAG读取的Markdown中。本次整理只改变文档包装，不改变原始正文，也不修改Agent或检索流程。

## 完整性的实际范围

“正文已保存”仅指本次浏览器可见的文字正文，不能扩大成“整篇图文均完整采集”。

- 图片目前未做OCR，轮播中尚未加载的其他图片也可能没有取得链接。
- 视频、评论及外链附件未转录。
- 图片中的路线、费用、地图等信息可能未包含在正文中；各文件均记录这一范围。
- 票价、班次、预约和营业时间反映作者当时的内容，未自动核验当前有效性。

完整正文与采集元信息同时保存在 `source_records/<笔记ID>.json`。本地校验将Markdown标记内的正文与源记录逐字比对，并核对源记录中的SHA-256，用于检查格式整理没有改变原文；哈希不再写入Markdown。保留原文不代表其中的事实已核验或当前仍然正确。

## 清单与核验文件

- `collection_plan.csv`：150个固定槽位，只有实际文件才填写来源与文件名；缺口标为待补齐。
- `collection_status.json`：实际总数、每城缺口、正文一致性和重复检查结果。
- `COLLECTION_INDEX.md`：按城市查看文件与原帖链接。
- `candidates_*.json`：已发现的真实候选，不等于已采集完成。
- `collection_report_*.json`：采集成功或失败的记录；历史成功记录可能已因质量复核被归档，正式清单以当前文件和校验结果为准。
- `excluded_notes.json`、`excluded_documents/`：复核排除的纯推广、穿搭或与目标城市无关的资料，保留审核依据，不进入RAG。
- `legacy_knowledge/`：原先10份人物地址示例的备份，不进入新的旅游知识库。
- `access_report.json`：早期3篇公开笔记的访问验证，仅为历史检查。
- `NOTE_TEMPLATE.md`：精简正文格式的参考模板，模板占位内容不计入采集结果。

## 维护

本目录不会被RAG直接读取。离线核验并更新清单：

部署包包含正式笔记、对应源记录及清单；候选、失败记录、旧示例备份和排除稿仅在本机保留，不进入部署包。

```powershell
.\.venv\Scripts\python.exe data\travel_collection\validate_collection.py
```

该命令只读取本地资料、核对原文与SHA-256、检查来源字段、重复笔记和城市内序号，并在校验通过后更新清单；失败时保留上次的清单、状态和目录。不调用外部模型或向量接口。

`note_format.py` 集中定义上述精简格式，采集器与校验器共用它；仅使用Python标准库，离线维护文档无需启动浏览器。

`collect_xhs.py` 为采集辅助脚本，使用已有的独立Playwright检查环境，不增加主项目运行依赖。普通公开笔记可从候选列表采集；需要登录的页面由本机独立浏览器正常登录并通过页面搜索和点击读取，不使用私有接口或绕过验证。

本次独立浏览器资料位于已被Git与Docker忽略的 `.uv-cache/`，不会打入部署包；没有读取用户日常浏览器资料或导出登录Cookie。
